# Сервер A.N.O.D.E

Игровой сервер и реестр серверов в одном файле. Ноль зависимостей — только встроенный
`http` из Node.js, поэтому на бесплатном хостинге он поднимается одним `git push`, без
сборки и без `npm install`.

Лежит здесь, в репозитории игры, по одной причине: **клиент и сервер обязаны понимать
один протокол**, и держать их описание в разных местах — верный способ однажды их
рассорить. Для развёртывания скопируй содержимое этой папки в корень отдельного
репозитория (как ты и хотел) — код от этого не меняется.

## Как поднять на Render

1. Создай пустой репозиторий и положи в его корень `server.js`, `package.json`,
   `render.yaml`, этот `README.md`.
2. В Render: **New → Web Service**, выбери репозиторий.
   - Runtime: **Node**
   - Build Command: оставить пустым
   - Start Command: `node server.js`
   - Health Check Path: `/health`
3. Во вкладке **Environment** выстави параметры (см. ниже).
4. Дождись первого деплоя и скопируй адрес вида `https://имя-сервиса.onrender.com`.
5. В игре: **ПО СЕТИ → ДОБАВИТЬ СЕРВЕР** → **ВСТАВИТЬ ИЗ БУФЕРА** → **ДОБАВИТЬ**.
   Карточка появится сразу, онлайн подтянется через пару секунд.

## Параметры (Environment)

| Переменная | Что задаёт | По умолчанию |
|---|---|---|
| `SERVER_NAME` | имя в списке серверов | `Сервер A.N.O.D.E` |
| `SERVER_DESC` | описание — раскрывается по тапу на карточке | пусто |
| `MAX_PLAYERS` | сколько человек пускать | `16` |
| `GAME_MAP` | какую карту поднять (`kordon`, `chast`, …) | `kordon` |
| `RULES` | правила мира: имена через запятую или число | пусто |
| `PUBLIC_URL` | свой адрес; Render подставляет его сам через `RENDER_EXTERNAL_URL` | из Render |
| `MASTER_URL` | адрес чужого списка, если этот сервер не мастер | пусто |
| `SUZHET` | сюжет в партии: `enable` / `disable` | `disable` |
| `MIN_NICK` | минимальная длина ника | `5` |
| `PORT` | порт; Render задаёт сам | `10000` |

## Хранилище профилей

Всё, что у игрока есть, живёт **на сервере**, а не в его телефоне: ник, деньги, рюкзак,
надетое, убийства, место выхода. Телефон это только показывает и просит изменить. Пока
инвентарь считался на клиенте, любой мог дописать себе экзоскелет правкой одного файла — и
остальные обязаны были это принять.

Профиль заводится сам при первом входе под новым ником; отдельной регистрации нет. Ник —
это имя учётной записи, поэтому он **не короче `MIN_NICK` символов** и **не может
совпадать с ником того, кто сейчас в игре** (сравнение регистронезависимое: «Вова» и
«вова» для человека одно имя).

| Переменная | Что задаёт | По умолчанию |
|---|---|---|
| `DATA_DIR` | куда класть `players.json` | `./data` |
| `SUPABASE_URL` | адрес проекта Supabase — тогда профили в настоящей базе | пусто |
| `SUPABASE_KEY` | сервисный ключ | пусто |
| `SUPABASE_TABLE` | имя таблицы | `players` |

**Без Supabase** профили лежат в JSON-файле. Это работает сразу и ничего не требует, но
на бесплатном тарифе Render диск эфемерный: файл переживает работу сервиса, но **не его
перезапуск и не деплой**. Для постоянства нужен либо диск, примонтированный в `DATA_DIR`
(платный тариф), либо Supabase.

**С Supabase** профили в настоящем Postgres. Выбран он потому, что это единственный
способ дотянуться до базы, не ставя ни одного npm-пакета: у Node есть встроенный `fetch`,
а у Supabase — HTTP поверх таблицы. Драйвер Postgres потребовал бы сборки, а вся затея
этого сервера — «git push и работает».

Таблица заводится один раз, в SQL-редакторе Supabase:

```sql
create table players (
  nick_key   text primary key,
  nick       text not null,
  money      integer default 0,
  kills      integer default 0,
  hp         real    default 100,
  x          real    default 0,
  y          real    default 0,
  z          real    default 0,
  inventory  jsonb   default '[]'::jsonb,
  equipment  jsonb   default '[]'::jsonb,
  seen_at    bigint  default 0
);
```

Профиль пишется при выходе игрока, при обрыве связи и раз в полминуты, пока он играет.
Рюкзак уходит на сервер и **вместе с прощанием**: всё, подобранное после последнего
удачного такта, известно только телефону, и другого случая это записать уже не будет.
Неудачный такт при этом не съедает изменение — пометка возвращается и уходит следующим.

**Если рюкзак всё-таки пропадает между заходами** — почти наверняка дело в диске Render, а
не в игре: на бесплатном тарифе он эфемерный, и `players.json` не переживает ни деплой, ни
пробуждение уснувшего сервиса. Лечится Supabase (ниже) — с ним профили лежат в настоящей
базе и переживают что угодно.

### Где граница доверия

Сервер отвечает за то, чтобы имущество **не терялось и не путалось между людьми**. Он не
разбирает, законно ли у человека появился экзоскелет: это значило бы перенести на сервер
весь подбор лута, торговлю и износ — то есть всю игру. Здоровье при этом сервер считает
сам и цифру от клиента принимает, только если она **меньше** известной ему.

### Правила (`RULES`)

| Имя | Что делает |
|---|---|
| `no_bots` | мир без бойцов вовсе — только живые игроки |
| `no_pvp` | пули между игроками не наносят урона |
| `all_friendly` | никто не агрится |
| `all_zombies` | режим смерти: весь мир — зомбированные, сюжетных персонажей нет |
| `no_traders` | торговцев нет, торговля недоступна |
| `army_hold` | армия всё захватила: наёмников нет, посты держат военные |
| `roleplay` | служба по РП — стрельбы между людьми нет, бойцы ходят своими маршрутами |
| `story` | сюжет: торговец, квестодатели и цепочка заданий (то же, что `SUZHET=enable`) |

Примеры:

```
RULES=all_zombies
RULES=army_hold,roleplay
RULES=no_bots,no_pvp
```

`roleplay` сам по себе выключает PvP и вражду — караул, расстреливающий проходящего,
никакой службы не отыграет. Клиент считает так же (`rulesNoPvp` в
`src/Game/Net/GameRules.cpp`), и расходиться этим двум местам нельзя.

## Несколько серверов

Список отдаёт любой сервер. Тот, чей адрес игроки вбили в игре, — мастер; остальным
пропиши `MASTER_URL=https://адрес-мастера.onrender.com`, и они будут раз в минуту
сообщать ему о себе. Сервер, молчавший пять минут, из списка пропадает.

## Протокол

Клиентская часть — `src/Game/Net/Multiplayer.h` и `src/Game/Net/ServerList.h`.

| Ручка | Что делает |
|---|---|
| `GET /health` | проверка живости для хостинга |
| `GET /servers` | список серверов: сам + зарегистрировавшиеся |
| `GET /info` | карточка этого сервера |
| `POST /register` | чужой сервер сообщает о себе |
| `POST /join` | вход: `{name, proto}` → `{ok, id, token, rules, seed, map, roster, profile}` |
| `POST /state` | такт: своё состояние → чужие состояния |
| `POST /leave` | выход — вместе с последним состоянием рюкзака |

**Сервер старой версии.** Если в ответе на `/join` нет `roster`, клиент понимает, что
сервер не знает про состав мира, пишет об этом в чат и водит бойцов сам. Раньше он в этом
случае просто переставал их считать, а присылать их было некому — весь мир замирал
столбами до конца партии, и причина была ниоткуда не видна.

**Кто чем владеет.** Всё. Клиент не решает про мир ничего.

| Что | Кто решает |
|---|---|
| ник, деньги, рюкзак, надетое, место выхода | сервер (профиль в БД) |
| здоровье игрока, попадания между людьми | сервер |
| чат, переводы денег, вещи на земле | сервер |
| **состав мира: кто вообще есть на карте** | **сервер** (`world.js`) |
| **где боты стоят, куда идут, в кого стреляют** | **сервер** (`ai.js`) |
| **кто кого убил и что осталось в теле** | **сервер** |
| высота земли под ногами, выталкивание из стен | клиент |
| поза, анимация, звук, интерфейс | клиент |

Ведущего-клиента больше нет. Раньше мир водил один из телефонов — у него боты шли без
задержки, у остальных с опозданием, а его выход перекидывал всю карту на другого. Теперь
мир один и он серверный: два человека, стоящие рядом, видят ботов в одних и тех же
точках, до второго знака после запятой.

**Почему высота и выталкивание остались на клиенте.** Это ЧИСТЫЕ ФУНКЦИИ от координат —
`terrainHeight(x,z)` и `kordonResolveCollisions` — и потому дают у всех один и тот же
результат до последнего бита. Считать их ещё и здесь значило бы портировать на сервер
рельеф и всю планировку Кордона: тысячи строк ради числа, которое и так совпадает.
Заодно это экономит четверть объёма записи о боте — Y по сети не ездит.

**Что из-за этого упрощено.** Сервер не знает про стены, поэтому его боты ходят к цели по
прямой, а от построек их отводят «запретные круги» (`OBSTACLES` в `ai.js`) — грубее, чем
ведение стены в одиночной игре, зато одинаково у всех. Клиентское выталкивание довершает
дело: в стену бот не войдёт ни у кого.

**Числа в `world.js` — копия игровых.** Ориентиры Кордона, таблица отрядов, имена и
клички повторяют `src/Game/World/Kordon.cpp` и `src/Game/AI/NPC.cpp`. Расходиться им
нельзя: отряд, поставленный сервером в чистое поле, у игрока окажется в стене. То же
касается `hostile()` в `ai.js` и `factionRelation` в игре.

**Здоровье считает сервер.** Клиент присылает своё, но принимается оно, только если
МЕНЬШЕ известного серверу: иначе достаточно не признавать урон, чтобы стать бессмертным.

## Замечание про бесплатный тариф

Render усыпляет бесплатный инстанс после четверти часа без запросов. Первый вход после
простоя ждёт, пока тот проснётся, — поэтому у запроса списка таймаут двенадцать секунд, а
у входа пятнадцать. Если сервер должен быть доступен всегда, нужен платный тариф или
внешний пинг раз в десять минут.

## Локально

```
cd server
PUBLIC_URL=http://127.0.0.1:8099 PORT=8099 SERVER_NAME="Локальный" node server.js
```

Затем в игре: **ПО СЕТИ → ДОБАВИТЬ СЕРВЕР** и адрес `http://127.0.0.1:8099`. С телефона —
адрес компьютера в той же сети Wi-Fi.
